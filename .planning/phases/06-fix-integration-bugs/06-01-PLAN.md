```python
def _hex_to_rgb(hex_color: str) -> np.ndarray:
    """Convert '#RRGGBB' hex string to float RGB array."""
    h = hex_color.lstrip("#")
    if not h:
        return np.array([0.0, 0.0, 0.0], dtype=np.float64)
    return np.array([int(h[0:2], 16), int(h[2:4], 16), int(h[4:6], 16)], dtype=np.float64)
```

The guard returns black (0,0,0) for empty strings or bare "#" inputs, preventing the `int('', 16)` ValueError that crashes `test_sse_progress` and `test_download_after_render`.

In `backend/app/services/rag_retriever.py`, inside the `query_styles` function, after the line `metadata["speed"] = float(metadata.get("speed", 0.5))` (line 68), add two lines that split the comma-string fields into proper arrays:

```python
        metadata["speed"] = float(metadata.get("speed", 0.5))
        # Split comma-joined strings into arrays for frontend consumption
        colors_raw = metadata.get("colors", "")
        metadata["colors"] = [c.strip() for c in colors_raw.split(",") if c.strip()] if colors_raw else []
        shapes_raw = metadata.get("shapes", "")
        metadata["shapes"] = [s.strip() for s in shapes_raw.split(",") if s.strip()] if shapes_raw else []
```

This converts `"#ff0000,#00ff00,#0000ff"` into `["#ff0000", "#00ff00", "#0000ff"]` and `"circles,triangles"` into `["circles", "triangles"]`. Empty strings produce empty arrays `[]`.

The `llm_blender.py` fallback function (`_fallback_blend`) also reads `colors` from the same metadata dicts returned by `query_styles`, so this fix simultaneously fixes both the frontend display (BUG-2) and the LLM blender's color extraction (which was silently treating the comma-string as a character sequence).
