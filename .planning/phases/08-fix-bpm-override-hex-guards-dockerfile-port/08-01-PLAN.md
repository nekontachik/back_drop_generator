**1. Fix bpm_override in generate-form.tsx (AUD-04):**

The bug: line 43 always sends `bpm_override=String(bpm)` when audioFile is present. Since `bpm` defaults to 120, this sends `bpm_override=120` on first submit, silencing librosa detection (backend sees bpm_override != None and uses it instead of detected BPM).

Fix: Track whether the user has explicitly interacted with the BPM slider. Add a `bpmTouched` boolean state initialized to `false`. Set it to `true` in the `setBpm` handler. Only append `bpm_override` to FormData when `audioFile` is present AND `bpmTouched` is true.

Concrete changes to `generate-form.tsx`:
- Add state: `const [bpmTouched, setBpmTouched] = useState(false);`
- Replace line `if (audioFile) { formData.append("bpm_override", String(bpm)); }` with:
  ```typescript
  if (audioFile && bpmTouched) {
    formData.append("bpm_override", String(bpm));
  }
  ```
- Change the BpmInput onChange prop from `onChange={setBpm}` to:
  ```typescript
  onChange={(v: number) => { setBpm(v); setBpmTouched(true); }}
  ```
- Reset bpmTouched when audio file is removed: in the `onFileChange` callback, add `setBpmTouched(false)` alongside `setDetectedBpm(null)` when `!f`.

**1. Fix Dockerfile CMD to use Railway PORT env var (DEP-02):**

Replace line 52:
```dockerfile
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

With a shell-form CMD that reads the PORT env var with fallback:
```dockerfile
CMD uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
```

This uses shell variable expansion so Railway's injected PORT env var is respected. The `:-8000` provides fallback for local development.

Also update the HEALTHCHECK to use the dynamic port. Replace line 48-49:
```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
```

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
```
